# 机制成本-收益审计报告

- 日期: 2026-08-29
- 触发: 用户质疑"工作流是否太死板" + 新需求"所有有 UI 项目强制出 preview.html"须最小集落地
- 审查方式: 全仓机制盘点 → 每个机制标注「防过的事故（证据追溯）+ 成本 + 建议」→ 形成降级/收敛整改清单
- 结论: 硬层（宪法/底线/门禁/漂移检测）全部保留且应精简不动；软层（流程义务/矩阵）存在 1 处过载 + 1 类无限膨胀趋势，需降级与设饱和线；"强制 preview.html"以最小集落地（不加门禁/矩阵/副本）

---

## 一、审计判定三原则

1. **可追溯**：机制必须指向一次真实事故（CHANGELOG Fixed / TECH-DEBT / audit 报告），"以防万一"不成立
2. **分层**：硬层（宪法、六条底线、门禁阻断项、漂移检测）精简不动；软层（播报/矩阵/轮数）必须有轻量档
3. **有饱和线**：矩阵类机制"覆盖已见 + 高频写法即停"，不追求无限全防
