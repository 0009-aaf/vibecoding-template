# 文档规范 — vibecoding-template

> 全部 docs/ 文档的元规范（编号 00，优先于其他文档）。vibe-plan 阶段 5 生成，长期有效。
> 本规范的执行不靠自觉：结构由 `scripts/check-sync.mjs` S6 机器校验，内容口径由 /vibe-audit 核对。

## 1. 编号体系

| 规则 | 说明 |
|---|---|
| 命名 | `docs/NN-NAME.md`，NN 两位数字 = vibe-plan 生成顺序，NAME 大写英文 |
| 现行编号表 | 00-DOC-STANDARD（本文件）/ 01-PRD / 02-ARCHITECTURE / 03-STATUS / 04-CONTRACTS / 05-DECISIONS / 06-RUNBOOK / 07-SECURITY / 08-CODING-STANDARDS / 09-DESIGN |
| 编号增删 | 新文档续用下一个空闲编号；编号与文件名一经发布不回收不复用（防引用断链） |
| 09 缺席 | 纯后端项目允许无 09-DESIGN（须在 02-ARCHITECTURE §1 或 PRD §3 说明"无 UI"） |
| 无编号白名单 | `DoD.md`（跨阶段底线）/ `TECH-DEBT.md`（implement 增量）/ `CHANGELOG.md`（项目根，面向使用者）/ `constitution.md`（项目根，最高约束）——四者不入编号体系，各有归属理由 |

## 2. 结构规范（每份 plan 期文档必备四件）

| # | 要件 | 格式 |
|---|---|---|
| S1 | H1 标题 | `# 文档名 — [项目名称]`（一处，全文唯一） |
| S2 | 引言 blockquote | H1 后紧跟：一句话用途 + 生成阶段 + 维护约定（谁在何时更新） |
| S3 | 编号章节 | `## N. 标题`，子节 `## N.x`；编号只增不重排（与检查项 M/G 编号同规矩） |
| S4 | 变更记录表 | 文末 `## 变更记录`（可带编号）：`日期 | 变更 | 原因`。例外：03-STATUS（状态文档本身）/ 04-CONTRACTS（@slice 标记承载变更）/ 05-DECISIONS（ADR 条目即变更记录）；模板侧例外：DoD-template（DoD 定稿不重谈，变更走 ADR） |

## 3. 内容规范

| # | 规则 | 示例 |
|---|---|---|
| C1 | 数值必须带单位与口径 | "响应 <200ms（P95）"而非"响应快" |
| C2 | "不适用"必须带理由 | "不适用(理由=本地单机无并发)" |
| C3 | 表格表头完整，空表不入仓（模板占位除外） | 表头列名即字段契约 |
| C4 | 禁止空洞形容词 | "高性能/高可用/现代化"→ 用 §3.1 NFR 量化替代 |
| C5 | 示例必须可直接执行 | 命令能跑通、路径真实存在、版本可复现 |

## 4. 交叉引用与术语

| # | 规则 |
|---|---|
| X1 | 文档引用：反引号相对路径，如 `docs/02-ARCHITECTURE.md`；禁止裸文件名或绝对路径 |
| X2 | 章节引用：`§N` 或 `§N.x`，紧跟所属文档引用之后 |
| X3 | 术语统一：同一概念全文档链同一词，以 `docs/02-ARCHITECTURE.md` §7 术语表为准（userId 不写作 user_id 叙述、切片不写作任务） |
| X4 | 检查项引用：M/G/S 编号原样引用（如 G05.5），不复述名称替代编号 |

## 5. 反臃肿原则

| # | 规则 |
|---|---|
| B1 | 规范类文档（00/07/08）约束总数 ≤35 条；超出部分指向 skill 层 |
| B2 | 单文档章节 ≤10；超了拆分或下沉模板 |
| B3 | 模板只放结构占位与规则，不放示例数据；示例数据进 dogfood 或 vault |

## 6. 校验与执行

| 层 | 机制 |
|---|---|
| 机器 | `node scripts/check-sync.mjs` S6：编号白名单外文件报漂移、必备四件缺失报漂移 |
| 审计 | /vibe-audit 文档同步检查项按本规范核对（编号/引用格式/变更记录） |
| 生成 | vibe-plan 生成任何 docs/ 文档前先读本文件 |
