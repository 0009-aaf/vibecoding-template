# Definition of Done（项目级完成底线）

> 由 `/vibe-plan` 从本模板生成到 `docs/DoD.md`。DoD 是**项目级固定底线**（per-project，恒定不变），
> 与切片验收标准 AC（per-task，随切片变化）互补。一个切片只有在 **AC 满足 且 DoD 全部勾选** 才算完成。
> 来源：addyosmani/agent-skills `references/definition-of-done.md`（MIT）。
> **DoD 一旦定稿不再逐次讨价还价** —— 每个 sprint 重谈的 DoD 不是 DoD。

## AC 与 DoD 的区别

| | 验收标准 (AC) | Definition of Done (DoD) |
|---|---|---|
| 范围 | 单个任务/切片特有 | 每个增量都适用 |
| 变化 | 每项不同 | 固定复用 |
| 回答 | "做对了这个事吗？" | "达到我们的完成标准了吗？" |
| 定义 | 规划任务时定义 | 项目开始时定义一次 |

## 固定清单

### Correctness（正确性）
- [ ] 该任务的全部 AC 满足
- [ ] 代码实际运行验证过，非仅编译/类型检查通过
- [ ] 新行为有测试覆盖，且该测试在改动前失败、改动后通过（红→绿）
- [ ] 既有测试全部通过，无回归
- [ ] 边界情况和错误路径已处理，非仅 happy path
- [ ] 新增安全/防御机制（guard、输入校验、权限、闸门）时，已用**误报/漏报矩阵**实测：合法操作不误伤、非法操作不漏网（"写了就当有用"不算验证）

### Quality（质量）
- [ ] 命名与结构体现意图，无需注释解释"做了什么"
- [ ] 无重复业务逻辑
- [ ] 无死代码、调试输出、注释掉的代码块残留
- [ ] 变更范围限定在任务内，无顺手重构（见项目宪法 `constitution.md` C2：精准修改 / NOTICED BUT NOT TOUCHING）
- [ ] lint 与格式检查通过

### Integration（集成）
- [ ] 变更与系统其他部分协同工作，非孤立通过
- [ ] 数据库迁移、配置变更、feature flag 已处理
- [ ] 公共接口/API 变更已考虑向后兼容

### Documentation（文档）
- [ ] 公共接口、API、用户可见行为已文档化
- [ ] 值得保留的架构决策已记录（ADR / `docs/03-STATUS.md`）
- [ ] 文档用永恒语言描述当前状态，而非变更历史

### Ship-readiness（交付就绪）
- [ ] 不可信输入、认证、数据处理的安全影响已评审（见 security-and-hardening）
- [ ] 新关键路径的可观测性已就位（日志/指标/追踪）
- [ ] 风险变更存在回滚路径
- [ ] 人类已完成评审并批准合并/部署

## 应用方式
- **每个增量**：检查 Correctness + Quality 后才算该增量完成
- **每个功能**：确认 Integration + Documentation 后才算功能完成
- **每次合并/发布**：完整清单是地板，发布流程（如 `ci-cd-deploy`）在其上追加部署门

## 红旗
- "完成了，只是还没运行过" —— 未验证的工作不算完成
- 把"测试通过"当作完成同义词，跳过文档/回归/运行时验证
- 截止压力下换一套更松的标准
- 把 AC 当全部底线，没有固定的质量地板
- 在需要人类评审的变更上，未经评审就宣布"完成"
- 防御机制只写不测，没打误报/漏报矩阵就上线（会带来"假安全感"）
