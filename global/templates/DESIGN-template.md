## 0. 设计源仲裁与硬约束

> 多个设计源同载时的冲突裁决顺序（实现时不得凭喜好混用、不得各取一半拼凑）：**硬约束红线 > 低保真灰阶纪律 > ui-ux-pro-max 数据输出 > frontend-design 审美建议**。
> 角色界定：`ui-ux-pro-max` = 数据供给（色板/字体/风格检索）；`frontend-design` = 方向审校否决权（防 AI 模板化默认脸）；`web-artifacts-builder` = HTML 预览产出工具；本文档 §1 令牌表 = 唯一落地锚点——任何来源与本表冲突，以本表为准并在此记录差异。
> 硬约束红线（对预览与正式实现同等生效）：界面零 emoji、零位图图片；图标一律内联 SVG 或 CSS 几何形（SVG 内禁嵌位图）；照片/Logo 位用灰阶占位盒 + `TODO(asset)` 注释，待用户提供真实素材后替换。机器校验见 quality-gate G05.7。

## 4. 交互状态规范（五态）

> AI 实现 UI 最常漏的部分：凡有数据渲染的组件，五态必须齐备（不适用(理由) 除外）。

| 状态 | 表现约定 | 触发 |
|---|---|---|
| loading | （如 skeleton 占位 ≥300ms 才显示 spinner，防闪烁） | 请求进行中 |
| empty | （如 空插画 + 一句引导文案 + 主行动按钮） | 数据为空 |
| error | （如 顶部错误条 + 重试按钮，文案来自错误码映射） | 请求失败 |
| disabled | （如 透明度 50% + cursor:not-allowed，禁止仅靠颜色） | 不可操作时 |
| skeleton | （如 首屏内容区骨架，与最终布局同构） | 首次加载 |

### 4.5 动效基线

> 数值为蒸馏基线（来源：Emil Kowalski 设计工程实践 + Material Design 3 motion 规范），切片实现对表执行、禁止临场发明；动画完备性永远让位于五态完备性与加载性能。

| 场景 | 时长 | 缓动 |
|---|---|---|
| 入场 / 展开 | 150–250ms | ease-out 系；ease-out 表示元素减速就位 |
| 出场 / 收起 | 取入场时长的 60–70% | 更陡曲线，快速离场不拖沓 |
| 模态 / popover | 200–500ms 内，全程交互等待 ≤300ms | 见下方推荐曲线 |
| tooltip | 125–200ms（复访可免延迟直出） | 同上 |
| 下拉菜单 / select | 150–250ms | 同上 |
| 按压反馈 | `:active` scale(0.97)，约 160ms | ease-out |

推荐 cubic-bezier 曲线：入扬 `(0.23,1,0.32,1)`；收退 `(0.77,0,0.175,1)`；弹层带轻微回弹 `(0.32,0.72,0,1)`。

实现规则：
- 只动 `transform` 与 `opacity`（合成属性，不触发重排）；
- 入场 scale ≥ 0.95 起步，禁止从 0 生长；
- 列表进场 stagger 间隔 30–80ms；
- 高频操作（100+ 次/天的控件）不做入场动画；
- `prefers-reduced-motion: reduce` 下时长减半、位移简化为淡入淡出，不做全量清零；
- hover 效果统一门控在 `@media (hover:hover)` 内，防触屏设备粘滞悬停。
